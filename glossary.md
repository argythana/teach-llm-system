## Lecture 01: Your laptop as an LLM server, choosing a model, prompts as code

- A **large language model (LLM)** is a model trained on a huge amount of text to
  continue a text; answering, writing and summarising are all continuations.
  ([`lec_01a` (intro)](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **central processing unit (CPU)** is the main processor of a computer: it runs every
  program, a few calculations at a time.
  ([`lec_01a` §0](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **graphics processing unit (GPU)** is a processor built for graphics that does
  thousands of simple calculations at once.
  ([`lec_01a` §0](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **RAM** is the computer's main memory, where running programs keep their data.
  ([`lec_01a` §0](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **VRAM** is the GPU's own memory, separate from the computer's RAM.
  ([`lec_01a` §0](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **`.env` file** is a plain-text file of `NAME=value` lines that holds your personal
  settings. It stays outside the code, so a secret, such as a password or an access key,
  never ends up in a notebook you share.
  ([`lec_01a` §0](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- An **environment variable** is a named value that the operating system keeps for
  programs, outside your code.
  ([`lec_01a` §0](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Weights** are the numbers a model learned in training; a model file is mostly
  weights.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- An **open model** is a model whose weights are published for anyone to download, such
  as the Qwen3 family this course uses.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **request** is what one program sends to another program to ask for one thing.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **response** is what the program sends back for one request: the result, or an
  error.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **server** is a program that runs in the background and handles requests at an
  address.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **client** is the code that sends requests to a server and reads its responses.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- An **API** is the set of requests a server understands, with the shape of each request
  and of its response.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Ollama** is a [local model server](https://docs.ollama.com/): it keeps a model in
  memory and handles requests at the address in `OLLAMA_HOST`.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Model parameters** are the numbers a model learns in training, its weights. The
  coefficients of a scikit-learn `LinearRegression` are parameters too.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Quantization** is storing each weight in fewer bits than the model was trained with,
  so the file is smaller and faster to read.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **provider** is a company that runs models on its own servers and sells their use
  over the internet.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **hosted model** is a model that a provider runs for you; your client sends each
  request to it over the internet.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- An **API key** is a secret that identifies your account with a provider; every request
  to a hosted model carries it.
  ([`lec_01a` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **prompt** is the text you send to a model.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- An **answer** is the text a model writes back for a prompt.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **token** is the unit of text a model reads and writes: a word, a word piece or a
  punctuation mark. Section 3 looks inside.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **stop token** is a token that a model writes to end its answer.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- An **endpoint** is one address of an API that handles one kind of request, such as
  Ollama's `/api/chat`.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **reasoning model** is a model trained to write out its reasoning before its answer.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Thinking** is the reasoning text a model writes before its answer, like working a
  problem on scrap paper.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **role** is the label that says who wrote one turn of a conversation: `user` for
  you, `assistant` for the model, `system` for the rules your code sets (`lec_01c`).
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **message** is one turn of a conversation: a dict with its `role` and its text, the
  `content`.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **chat model** is an LLM trained to continue a conversation of messages with the
  next answer.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **hallucination** is an answer that states something false or made up, as fluently
  and confidently as a true one.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **special token** is a token reserved for structure, such as the start or the end of
  a message, that never stands for ordinary text; the stop token is one.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Tokens per second** is a model's writing speed: the tokens of the answer divided by
  the seconds spent writing them.
  ([`lec_01a` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- The **vocabulary** is the fixed list of every token a model knows, about 151 000 for
  Qwen3.
  ([`lec_01a` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **token ID** is the number that stands for one token: its position in the
  vocabulary.
  ([`lec_01a` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **tokenizer** is the program that cuts text into tokens and replaces each with its
  token ID.
  ([`lec_01a` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- The **Hugging Face Hub** is the website where model makers publish their models'
  files, one page per model, such as
  [`Qwen/Qwen3-1.7B`](https://huggingface.co/Qwen/Qwen3-1.7B); `lec_01b` explores it.
  ([`lec_01a` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- The **context window** is the maximum number of tokens that a model can work with at
  once: your messages plus the model's answer.
  ([`lec_01a` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Truncation** is cutting off the part of a text that does not fit a limit.
  ([`lec_01a` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Sampling** is drawing the next token at random, weighted by the probabilities the
  model gave each token.
  ([`lec_01a` §5](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- **Temperature** is a setting that reshapes the token probabilities before the draw: at
  `0` the most likely token is picked every time; higher values flatten the
  probabilities, so less likely tokens get a chance and we get increased randomness.
  ([`lec_01a` §5](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01a_first_call_tokens_context.ipynb))
- A **license** is the set of legal terms that say what you may do with a model's files,
  such as commercial use or shipping in a product.
  ([`lec_01b` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **requirement** is a condition a model must meet for the system to do its job.
  ([`lec_01b` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **requirements table** is the list of a system's requirements, one row each, written
  before looking at any model.
  ([`lec_01b` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- **Latency** is the time a user waits for an answer; for a chat model it follows from
  tokens per second (`lec_01a`).
  ([`lec_01b` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **repo id** is the name of a model repository on the Hub, `<owner>/<name>`, such as
  `Qwen/Qwen3-1.7B`. Every library and server names a model by its repo id.
  ([`lec_01b` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **gated model** is a model whose files the Hub serves only to accounts that accepted
  its license.
  ([`lec_01b` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **read token** is the Hub's API key (`lec_01a`): a secret that lets code download
  files as your account. Despite its name, it is not a token of the kind a model reads.
  ([`lec_01b` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **tag** is a short label attached to an item so that search can filter by that
  label, such as a model's language or task on the Hub.
  ([`lec_01b` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- **Fine-tuning** is training a trained model further on examples of one task, such as
  instructions and their answers.
  ([`lec_01b` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **base model** is a model before any fine-tuning: it only continues the text you
  give it.
  ([`lec_01b` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **model card** is the `README.md` of a model repository: a short document saying
  what the model is meant for and how well it works.
  ([`lec_01b` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- **Metadata** is data about other data: for a model, fields such as its license and
  languages, as opposed to the weights themselves.
  ([`lec_01b` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **permissive license** is a license that allows any use, including commercial, as
  long as you keep the license notices.
  ([`lec_01b` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- An **inference engine** is the program that runs a model: it does the arithmetic that
  turns a prompt into an answer, such as the C++ library
  [`llama.cpp`](https://github.com/ggml-org/llama.cpp) inside Ollama.
  ([`lec_01b` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- **GGUF** is the file format of `llama.cpp`, and so of Ollama: one file holds the
  quantized weights and what is needed to run them, such as the tokenizer
  ([Hub docs](https://huggingface.co/docs/hub/gguf)).
  ([`lec_01b` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- **llmfit** is a [command-line program](https://github.com/AlexsJones/llmfit) that
  estimates which models your hardware can run, and how fast, without downloading any
  (guide `01b_llmfit`).
  ([`lec_01b` §5](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- **JSON** is a [text format for data](https://www.json.org/json-en.html) that programs
  exchange, built from objects like dicts, arrays like lists, strings, numbers, `true`,
  `false` and `null`.
  ([`lec_01b` §5](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **decision record** is a short note, kept next to the code, that captures one
  decision and its reasons.
  ([`lec_01b` §8](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01b_choosing_a_model_requirements_hf_hub.ipynb))
- A **chat template** is a recipe, shipped with a model, that lays a list of messages
  out as one text, with special tokens (`lec_01a`) marking where each message starts and
  ends and its role.
  ([`lec_01c` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- A **refusal** is an answer in which the model declines the request instead of
  answering, such as "I can't help with that" or "The notes don't say".
  ([`lec_01c` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- A **system prompt** is the text of the `system` message: the product rules, such as
  tone, language, refusals and format.
  ([`lec_01c` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- A **shot** is one worked example, a question with its answer, placed inside a prompt.
  ([`lec_01c` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- A **zero-shot prompt** is a prompt with the instruction only, no shots.
  ([`lec_01c` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- A **few-shot prompt** is a prompt with the instruction plus a few shots.
  ([`lec_01c` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Parsing** is turning text into values a program can use, such as a category name or
  a number.
  ([`lec_01c` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Structured output** is an answer in a fixed, machine-readable format instead of
  prose, so a program can parse the answer without guessing.
  ([`lec_01c` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- A **JSON schema** is a dictionary that describes the shape of a JSON object: its keys,
  the type of each value, and which keys are required
  ([guide](https://json-schema.org/learn/getting-started-step-by-step)).
  ([`lec_01c` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Constrained decoding** is generating an answer while allowing, at each step, only
  the tokens that keep the answer valid against a JSON schema.
  ([`lec_01c` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Caching** is saving a result on its first computation, and reading the saved copy
  afterwards instead of computing the result again.
  ([`lec_01c` §5](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Streaming** is sending an answer piece by piece while the model writes, instead of
  all at once at the end.
  ([`lec_01c` §6](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Time to first token** is the time from sending a prompt to receiving the first piece
  of its answer.
  ([`lec_01c` §6](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01c_prompts_roles_structured_output.ipynb))
- **Retrieval** is searching your own documents for the passages that answer a question,
  so that a model can answer from the passages found.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- A **framework** is a library that solves the problems many applications share, once:
  it defines the parts and how they connect, and you supply the prompts and the model.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- **LangChain** is a
  [framework](https://docs.langchain.com/oss/python/langchain/overview) for LLM
  applications, the most widely used one.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- A **LangChain chat model** (`ChatOllama`) is the LangChain object for a chat model
  (`lec_01a`): it sends messages to the model and returns its answer as a message; you
  wrote `client.chat(...)`.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- A **prompt template** (`ChatPromptTemplate`) is a prompt with named slots in curly
  braces, filled in at run time; you wrote `build_prompt_from(question, style)`.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- An **output parser** (`StrOutputParser`) is a LangChain object that turns the model's
  message into what your code wants; you wrote `.message.content.strip()`.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- A **chain** is a sequence of parts joined with `|` and run in order as one object: the
  output of each becomes the input of the next.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- A **Runnable** is any LangChain object with the three methods `invoke`, `batch` and
  `stream`
  ([reference](https://reference.langchain.com/python/langchain-core/runnables)); every
  part and every chain is one.
  ([`lec_01d` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- The **LangChain Expression Language** (LCEL) is the `|` notation that joins LangChain
  parts into a chain; the result is itself a Runnable.
  ([`lec_01d` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- **Concurrency** is the number of requests a server handles at the same time.
  ([`lec_01d` §3](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- An **OpenAI-compatible API** is an API that accepts the request format of OpenAI's
  API, so that one client can talk to many providers.
  ([`lec_01d` §4](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))
- A **class** is a named template for objects: it lists the data each object holds and
  the functions it offers. You have used classes, such as `DataFrame` and
  `GridSearchCV`; the Python course did not teach writing them.
  ([`lec_01d` §6](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01d_langchain_chains.ipynb))

### Optional / career-track notebooks

- A **causal language model** (causal LM) is a model that predicts the next token from
  the preceding tokens only; every chat model in this course is one.
  ([`lec_01e` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01e_run_a_model_with_transformers.ipynb))
- A **tensor** is an array like NumPy's that can also live on a GPU.
  ([`lec_01e` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01e_run_a_model_with_transformers.ipynb))
- **Safetensors** is a file format for weights that holds only numbers, so loading a
  file cannot run code, as older PyTorch files could: a risk with files downloaded from
  the internet.
  ([`lec_01e` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01e_run_a_model_with_transformers.ipynb))
- **pydantic** is a Python library that turns a class describing the fields of an answer
  into a JSON schema, and checks data against that schema.
  ([`lec_01f` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01f_pydantic_and_hosted_inference.ipynb))
- **Validation** is checking data against declared types and allowed values, and
  refusing data that does not fit.
  ([`lec_01f` §1](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01f_pydantic_and_hosted_inference.ipynb))
- **Hosted inference** is running a model on a provider's hardware: your code sends each
  request over the internet and gets the answer back.
  ([`lec_01f` §2](lecture_01_ollama_models_prompts_langchain/reading_material/lec_01f_pydantic_and_hosted_inference.ipynb))

## Lecture 02: Embeddings, retrieval and a vector store

- A **vector** is a fixed-length list of numbers.
  ([`lec_02a` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02a_embeddings_cosine_similarity.ipynb))
- An **embedding model** is a model trained so that texts with similar meaning get
  nearby vectors.
  ([`lec_02a` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02a_embeddings_cosine_similarity.ipynb))
- An **embedding** is the vector that an embedding model assigns to a text; to *embed* a
  text is to compute its embedding.
  ([`lec_02a` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02a_embeddings_cosine_similarity.ipynb))
- The **dimension** is the length of an embedding model's vectors, fixed per model (768
  here).
  ([`lec_02a` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02a_embeddings_cosine_similarity.ipynb))
- **Cosine similarity** is a measure of how closely two vectors point the same way:
  `a · b / (|a| |b|)`, 1 for the same direction and 0 for vectors at right angles.
  ([`lec_02a` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02a_embeddings_cosine_similarity.ipynb))
- **Keyword search** is searching by counting the words that each document shares with
  the question.
  ([`lec_02a` §4](lecture_02_embeddings_rag_vector_store/reading_material/lec_02a_embeddings_cosine_similarity.ipynb))
- **Retrieval-augmented generation (RAG)** is a way of making a model answer from your
  documents: search them for the passages closest to the question, and send those with
  the question.
  ([`lec_02b` (intro)](lecture_02_embeddings_rag_vector_store/reading_material/lec_02b_hand_built_rag.ipynb))
- A **splitter** is code that cuts a long text into smaller pieces at chosen places,
  such as headings.
  ([`lec_02b` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02b_hand_built_rag.ipynb))
- A **retriever** is the part of a RAG system that finds the passages for a question;
  here it is `retrieve_sections_for`.
  ([`lec_02b` §4](lecture_02_embeddings_rag_vector_store/reading_material/lec_02b_hand_built_rag.ipynb))
- **Chunking** is cutting documents into pieces small enough to embed and focused enough
  to match one question.
  ([`lec_02c` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02c_chunking_size_overlap_metadata.ipynb))
- A **chunk** is one piece of a document cut by chunking: the unit a RAG system embeds
  and retrieves.
  ([`lec_02c` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02c_chunking_size_overlap_metadata.ipynb))
- The **chunk size** is the maximum length of a chunk, here counted in characters.
  ([`lec_02c` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02c_chunking_size_overlap_metadata.ipynb))
- A **separator** is a string at which a splitter may cut a text, such as a heading
  mark, a blank line, a line break or a space.
  ([`lec_02c` §3](lecture_02_embeddings_rag_vector_store/reading_material/lec_02c_chunking_size_overlap_metadata.ipynb))
- **Overlap** is the text that two neighbouring chunks share: the end of each chunk
  repeated at the start of the next.
  ([`lec_02c` §4](lecture_02_embeddings_rag_vector_store/reading_material/lec_02c_chunking_size_overlap_metadata.ipynb))
- A **`Document`** is LangChain's object for a text with its metadata: `page_content`
  (the text) and `metadata` (a dict).
  ([`lec_02c` §5](lecture_02_embeddings_rag_vector_store/reading_material/lec_02c_chunking_size_overlap_metadata.ipynb))
- A **query** is the text a search runs with, usually the user's question.
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- A **database** is software that keeps data on disk for programs to search, add to and
  change.
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- A **vector store** is a database for vectors: it stores each one with its text and
  metadata, and returns the nearest ones to a query.
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Chroma** is an open-source vector store that runs inside Python and keeps its data
  in a folder ([docs](https://docs.trychroma.com/)).
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- A **collection** is one named set of vectors inside a vector store, like a table in a
  database.
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- An **id** is the unique name of one item, such as one stored chunk.
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- An **index** is the searchable store of a set of documents' vectors, with a structure
  that finds near neighbours without comparing the query with every vector (not the
  index of a DataFrame). Chroma's structure is
  [HNSW](https://en.wikipedia.org/wiki/Hierarchical_navigable_small_world).
  ([`lec_02d` §1](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Ingestion** is loading documents into a vector store: cutting them into chunks,
  embedding the chunks and storing them.
  ([`lec_02d` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- An **idempotent operation** is an operation whose result is the same after one run or
  after many.
  ([`lec_02d` §2](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Cosine distance** is 1 minus the cosine similarity of two vectors (`lec_02a`): 0 for
  the same direction, so a lower distance means a closer chunk.
  ([`lec_02d` §3](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- A **metadata filter** is a search condition on a chunk's metadata, such as its `kind`,
  that keeps only the matching chunks.
  ([`lec_02d` §4](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- A **content filter** is a search condition on a chunk's text, such as containing an
  exact term, that keeps only the matching chunks.
  ([`lec_02d` §4](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Hybrid search** is searching by exact words and by meaning at once, and combining
  the two rankings.
  ([`lec_02d` §4](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- An **evaluation set** is a set of questions with known good answers, used to measure a
  system on many questions instead of one.
  ([`lec_02d` §6](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Hit rate@k** is the share of the questions for which a chunk of the file that
  answers the question is among the top `k` results.
  ([`lec_02d` §6](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Mean reciprocal rank (MRR)** is the average of 1 divided by the rank of the first
  chunk from the file that answers the question: 1 if it is always first, 0.5 if always
  second, 0 if it is not in the top 8.
  ([`lec_02d` §6](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))
- **Query rewriting** is a model call before the search that turns the question into a
  query in the documents' terms.
  ([`lec_02d` §7](lecture_02_embeddings_rag_vector_store/reading_material/lec_02d_chroma_retriever_langchain_rag.ipynb))

## Lecture 03: Evaluation, LLM judges and agents

- A **scorer** is a function that grades one answer and returns a number, or True or
  False.
  ([`lec_03a` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **verdict** is the value a scorer returns for one answer.
  ([`lec_03a` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **deterministic scorer** is a scorer written as plain code, so the same answer
  always gets the same verdict.
  ([`lec_03a` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **trace** is the stored history of one end-to-end call of an application, such as
  one `rag_chain.invoke(...)`.
  ([`lec_03a` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **span** is the stored history of one step inside a trace, with its inputs, outputs
  and duration; spans nest inside each other.
  ([`lec_03a` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **span type** is the kind of step a span stores: `RETRIEVER`, `CHAT_MODEL`, `CHAIN`
  (a pipeline of steps).
  ([`lec_03a` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- **Tracing** is recording every call of an application as a trace.
  ([`lec_03a` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- **Token usage** is the number of tokens one call read and wrote: what a hosted
  provider would bill, here the prompt with its four chunks plus the answer.
  ([`lec_03a` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **decorator** is a line starting with `@` right before a `def`, which wraps the
  function so that every call goes through the wrapper first.
  ([`lec_03a` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **record** is one question of an evaluation set in the form MLflow reads: a dict
  with the keys `inputs` and `expectations`.
  ([`lec_03a` §3](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- An **evaluation run** is an MLflow run that holds every answer of one evaluation, with
  its trace and its verdicts.
  ([`lec_03a` §5](lecture_03_evaluation_judges_agents/reading_material/lec_03a_tracing_and_deterministic_scorers.ipynb))
- A **rubric** is the set of grading instructions a judge follows.
  ([`lec_03b` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03b_llm_judge_comparing_variants.ipynb))
- A **rationale** is the explanation a judge logs next to its verdict (`lec_03a`).
  ([`lec_03b` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03b_llm_judge_comparing_variants.ipynb))
- A **judge model** is the model that grades; here the local chat model that also
  answers.
  ([`lec_03b` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03b_llm_judge_comparing_variants.ipynb))
- An **LLM judge** is a scorer that sends the answer and a rubric to a judge model and
  reads back a verdict, here `yes` or `no`, with its rationale.
  ([`lec_03b` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03b_llm_judge_comparing_variants.ipynb))
- A **variant** is one version of a system, run on the same questions and scorers as the
  others so that the results compare.
  ([`lec_03b` §3](lecture_03_evaluation_judges_agents/reading_material/lec_03b_llm_judge_comparing_variants.ipynb))
- A **reference label** is the verdict an answer should get by the rubric, written down
  before any judge sees the answer.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- **Agreement** is the share of answers on which judge and label agree: the accuracy of
  a classifier.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- A **false yes** is a verdict `yes` on an answer labelled `no`.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- A **false no** is a verdict `no` on an answer labelled `yes`.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- A **lenient judge** is a judge that gives many false yes verdicts: it passes wrong
  answers.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- A **strict judge** is a judge that gives many false no verdicts: it fails right
  answers.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- The **false-yes rate** is the share of the answers labelled `no` that the judge
  passes.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- A **judge bias** is a systematic pull on the verdict from something the rubric does
  not ask about.
  ([`lec_03c` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03c_judging_the_judge.ipynb))
- An **action** is work that needs code rather than text, such as counting across files,
  a lookup or a calculation.
  ([`lec_03d` §1](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- A **tool** is a Python function that the model may ask your code to run, described by
  a name, a description and typed arguments.
  ([`lec_03d` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- A **tool call** is the model's request to run a tool: a tool name and argument values,
  written instead of an answer.
  ([`lec_03d` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- A **tool result** is what the tool returned, sent back to the model as a message.
  ([`lec_03d` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- A **type hint** is a note after an argument's name, such as `term: str`, that names
  the type the argument must have; `-> dict` names the type returned
  ([Python glossary](https://docs.python.org/3/glossary.html#term-type-hint)).
  ([`lec_03d` §2](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- An **agent** is a program that runs a model in a loop of tool calls and tool results,
  in which the model decides which tool to call next and when to stop and answer.
  ([`lec_03d` §3](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- **LangGraph** is a [library](https://docs.langchain.com/oss/python/langgraph/overview)
  from the LangChain team for systems that decide and loop, built from LangChain's
  parts.
  ([`lec_03d` §6](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- A **hard limit** is a cap, written in code, on how many steps a loop may take, so that
  the loop always ends.
  ([`lec_03d` §6](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))
- **Prompt injection** is text that a model reads as data, such as a retrieved note, but
  follows as an instruction
  ([OWASP](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)).
  ([`lec_03d` §7](lecture_03_evaluation_judges_agents/reading_material/lec_03d_tools_and_agents.ipynb))

- **Held-out questions** are questions kept away from the optimizer and used once, at
